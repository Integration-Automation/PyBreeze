## U-20261008-03 · 2026-10-08 · One JSON document for a text editor and a visual editor · #feature #json #roadmap

- **What**: the third shared contract of Phase 0 of the automation platform roadmap (pull request #141): where the line runs between a JSON text and its tree, so a visual editor can sit beside the text editor without the two overwriting each other.
  - `utils/json_format/json_document.py`: a `JsonDocument` is the one copy both edit. Its text is the truth and is kept exactly as given, also while it is not JSON: nothing raises, `problem` says what is wrong (with the line and column for a syntax error) and there is no tree until the text parses again.
  - The tree holds what the text says and nothing of its layout. A number is a `JsonNumber` that keeps its text, so `1.0` and `1e400` come back as written; an object keeps its members in the text's order.
  - A tree becomes text only through `serialize_json(tree, SerializationOptions)` (indent, `ensure_ascii`, a trailing line break): layout lives there and nowhere else. The default layout is the JSON tools' own (`pretty_json_or_none`), and the text goes through `escape_for_view` like theirs.
  - `set_text()` and `set_tree()` each name the revision the edit was made against. An edit made against an older revision raises `StaleRevisionError` and changes nothing, instead of overwriting what the other side did in between.
  - `parse_json()` refuses what the JSON tools refuse (a key twice in one object, `NaN`, `Infinity`) and logs nothing: an editor asks on every keystroke.
  - `json_process._Numbers` is public as `HeldNumbers`, since the document writes numbers back through it.
  - Inserting, deleting, reordering and renaming nodes, undo and the unsaved mark are Phase 5, with the editor itself.
- **Result / numbers**: `test_json_document.py`, 60 tests. Two are property tests over JSON text with numbers in several spellings: a tree written and read again is the same tree, and the default layout is character for character what `pretty_json_or_none` gives.

## U-20261008-04 · 2026-10-08 · One way to ask a framework for completion and diagnostics · #feature #language-service #roadmap

- **What**: the fourth shared contract of Phase 0 of the automation platform roadmap (pull request #141): a language-service adapter contract for AutoControl, WebRunner and LoadDensity.
  - `utils/language_service/service_adapter.py`: a `LanguageServiceAdapter` names its framework (the package's import name), says what it can do (`capabilities()`: completion, diagnostics, hover, definition) and answers. Completion and diagnostics are abstract, the minimum every adapter gives; hover and go-to-definition are optional and give nothing unless overridden. `capabilities()` is asked before every request, because the answer depends on the framework version installed.
  - The types are the Language Server Protocol's (`Position`, `Range`, `TextDocument`, `Diagnostic`, `Severity`, `CompletionItem`, `Hover`, `Location`), so an adapter can later sit in front of a real language server without the editor's side changing. `Position.character` counts UTF-16 code units, the protocol's default and what Qt's text cursor counts in; `utf16_offset()` and `index_at()` convert to and from a Python index.
  - The editor goes through a `LanguageService`, never the adapter: it asks only for what the adapter says it can do, and an adapter that raises (also from `capabilities()`) is logged and gives an empty answer. A `LanguageServiceRegistry` holds one service per framework.
  - No adapter exists yet and no framework is imported here: the adapters are Phase 6 (WebRunner, then AutoControl, then LoadDensity).
- **What the guard does not do**: it stops exceptions. A framework that crashes or hangs the interpreter is not stopped by a `try`, so an adapter that loads a framework's code has to do it in a child process, as the executors do. `je_auto_control` must not be imported in the IDE process in any case (`CLAUDE.md`, Conventions).
- **Result / numbers**: `test_language_service.py`, 27 tests: an adapter is asked only for what it says it can do, a changed answer from `capabilities()` is honoured on the next request, each failure is logged with the framework's name and what was asked, and a position made from an index leads back to it for any text.

## U-20261008-11 · 2026-10-08 · A JSON editor: one document as a tree and as text, with one history · #feature #tools #json #roadmap
